# 溪巷工坊·共享工具站节律分型

溪巷工坊是一个模拟的社区工具共用网络，设有 12 个修造站、邻里共享点和自助工具柜。协调组用一周的分时归还记录找到节律相近的站点，按组试排值守，再逐站核对异常。

## 工作背景

上游由站点联络人汇总工具柜日志与纸质回收联。过去，协调组在共享表格中手抄数据、画分时百分比、把值班意见发到群里。人手紧时，件数大的站点会盖过小站的节律，自助柜夜间归还容易被白班补记，表格改动也会让旧群消息失去依据。工具站临时关门时，关门那几小时曾被算成「无人归还」，既拉低了站点的归还节律，也让闭站期间补进来的联单无处安放。

本站从核对小时台账开始，冻结一次分型用到的站点名单、日期、参数、归还向量与闭站登记。负责人拿到三个输入量级的区分：可以按组安排的站点、需要逐站核实的例外、完全缺数据的站点。发布后，站点联络人可通过 CSV 逐站领取值守或复核任务。闭站允许补登；闭站时段内的归还记录原样保留、只标记为闭站冲突凭据，绝不删除或改写原始记录。

| 账号 | 角色 | 页面权限与典型动作 |
|---|---|---|
| `analyst` 周禾 | 分析员 | 登记站点、补录和校正分时归还，提交计算版本，查看全部分型与已发布值班单 |
| `admin` 韩宁 | 值班负责人 | 查看全部分型，修改各组建议，填写每个例外的处置意见并发布 |
| `observer` 宋可 | 观察员 | 只读站点和归还台账，查看已发布的分型和值班单，下载 CSV |

## 分型口径与复算

- 输入日期按北京时间，起止日均含。小时先归入本地半开时段 `[00,08)`、`[08,11)`、`[11,14)`、`[14,17)`、`[17,20)`、`[20,24)`。每站按窗口对六段归还件数求和，缺失时段按零填充。整站零件为「无记录」，正数但低于门槛为「低样本」。
- **闭站登记**按半开小时区间 `[起日起时, 止日止时)` 保存，同站区间不得交叠，最长 93 天。闭站允许事后补登；闭站时段内已录入的归还不删除、不改写，单独累计为「闭站冲突件数」并在台账标记，作为复核凭据。闭站登记与归还记录在同一事务、同一时点读入快照，两类数据同时补录时也会进入同一个分型版本。
- **开放小时口径**：每个时段的名义小时数为窗口天数乘以时段长度，减去该站落在该时段的闭站小时数，得到开放小时数。节律向量各分量取「开放时段归还件数 ÷ 开放小时数」，闭站时段的件数和小时同时剔除；某时段整段关闭时该分量记零且不参与该站的相似度比较。整站开放时段零件为「无记录」，有冲突件数但开放零件时同样按无记录处理并提示先核对闭站联单。
- 对进入计算的向量 `x` 做 L2 归一化。两站只在彼此共同开放的时段上计算余弦距离 `d(x,y) = 1 − Σ共同(xᵢyᵢ)/(√Σ共同xᵢ²·√Σ共同yᵢ²)`；完全没有共同开放时段的两站不相邻。闭邻域使用 `d ≤ ε`，容许 `1e-12` 的浮点误差，邻居计数含本站。
- DBSCAN 以编号排序的核心站扩展密度连通组，同行遍历邻居时也按编号排序。可达多组的边界站归到先扩展的组。扩展新成员时额外要求该站与组内全体成员至少有一个共同开放时段，因此每个成组都能指出各站共同开放的时段；因共同开放时段为空而被拦下的邻近站保留为「失群」并注明原因。未归入任何组的合格站标作「失群」。`G01` 等编号的作用域为当前版本。
- 画像按站等权，且只在组内各站共同开放的时段上平均：每站 `p[i] = 开放件数[i]/开放小时[i]`，组画像为各站 `p` 的算术平均，最高占比对应主峰，非共同开放时段留空。相同时取最早时段。并列结果和低样本情形都可读，空合格集会产出零组及逐站诊断。
- 每个版本保存算法标识 `cosine-dbscan-v2`、参数、时段边界、窗口天数、名义与开放小时数、闭站登记、各站原始件数/剔除件数/开放小时和站点名称及编号。对规范化的 UTF-8 JSON（键排序、无空格）计算 SHA-256。相同快照产生相同指纹与结果，后来补录、修改参数或新增站点只影响新版本。`cosine-dbscan-v1` 的旧快照与结果原样留存、可继续查阅；升级后仍排队的 v1 版本会按快照校验失败处理，由分析员用 v2 重新提交。
- MySQL 保存任务和结果。Redis 唤醒 worker，轮询兜底。worker 用连接级互斥锁按版本号串行消费，进程中途退出后可重新领取未完成版本。快照校验或计算错误会留下失败态。发布与审计在同一事务内落库。闭站登记的新增、删除与闭站冲突凭据均写入审计。

```sh
cp .env.example .env
docker compose up --build --wait
# 如关闭了自动 seed，可执行下面一行装载模拟数据。
docker compose exec -T backend python -m scripts.seed_demo
```

- 前端 `http://127.0.0.1:18275`，API `http://127.0.0.1:19275`，FastAPI 的 `/docs` 可查看接口契约。
- MySQL `127.0.0.1:17775`（容器端 3306），默认库名 `tool_rhythm`。Redis 在 Compose 内部网络。
- 修改前端模块后执行 `docker compose up -d --build frontend`。修改后端后重建 `backend worker`。本机 Python 3.11 可运行纯计算模块，数据库相关路径使用 Compose 测试。局部开发停止用 `docker compose down`。清除演示数据后重建时可用 `docker compose down -v --remove-orphans`。
- 本批实际验收统一从批次根运行 `bash scripts/verify-project.sh gb-5206`。测试及结果在 `test-artifacts/gb-5206/`。

## 已知限制

单次日期窗口为 1–93 天、最多 250 站，邻域比较为平方复杂度。当前录入粒度是站点/日/小时汇总，闭站登记最小粒度也是一小时，来源联单作为文本留存。窗口全零无法区分休站、漏录和确实无人归还，需要联系站点核实；闭站登记只解释已登记的关门时段，未登记的关门仍会按开放小时计入分母。闭站冲突凭据仅做标记与剔除，是否追责或补录由负责人逐站判断。节律分组反映归还分布，实际值守人手由负责人结合工具类型和现场负荷安排。应用为本地模拟环境，外部字体不可用时会使用本机中文字体。源代码按 MIT License 提供。
